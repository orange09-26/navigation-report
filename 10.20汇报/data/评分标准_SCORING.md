# 评分标准（完整公式）

本文件定义本次 MapGPT 升级实验的**全部**打分公式。所有指标都由脚本从日志直接计算，
无任何人工填写；升级组（v3）与基线组（v2）使用**完全相同**的公式重算，可直接对比。

符号约定（单局 i，共 N 局；单步 t，该局共 T_i 步）：

| 符号 | 含义 | 来源 |
|---|---|---|
| `l_i` | 起点到终点的最短路径长度（格边数，四连通 BFS） | 仿真器真值 |
| `p_i` | 实际前进成功次数（`FORWARD` 且未撞墙） | 日志 |
| `S_i` | 成功标志，到达终点则 1，否则 0 | 日志 |
| `d_t` | 第 t 步**结束后**机器人所在格到终点的最短步数（真值 BFS） | 评测侧计算 |
| `AP_{i,t}` | 第 t 步模型自建地图与真值地图的一致度 | 模型 `<MAP>` 输出 |

---

## 一、局级指标（共 10 项）

**1. 成功率 SR**

```
SR = (1/N) · Σ_i S_i
```

**2. SPL（标准定义，Anderson et al. 2018）**

```
SPL = (1/N) · Σ_i [ S_i · l_i / max(p_i, l_i) ]
```

失败局贡献 0。这是论文使用的口径，**本次升级后作为主指标**。

**3. SPL_succ_only（仅成功局均值，旧版口径）**

```
SPL_succ_only = (1/N_succ) · Σ_{i: S_i=1} l_i / max(p_i, l_i)
```

> ⚠️ 2026-10-12 那份汇报里的 SPL=0.9221 用的是这个口径（只对成功局求平均）。
> 换算成标准口径应为 0.9 × 0.9221 = **0.8299**。本次起统一改用标准口径，两个数都列出以便追溯。
> 本次基线 ep00–09 全部成功，所以两个口径数值相同（0.8765）。

**4. Oracle 成功率 OSR**

```
OSR = (1/N) · Σ_i 1[ 终点格 ∈ 该局轨迹 ]
```

衡量「有没有走到过终点」（哪怕最后没停下来）。

**5. 导航误差 NE**

```
NE = (1/N) · Σ_i d_BFS(最终位置_i, 终点_i)
```

若最终位置到终点在真值地图上不可达，退化为曼哈顿距离。单位：格。

**6. 建图精度 AP**

```
AP_{i,t} = mean( cell_acc_{i,t} , edge_Jaccard_{i,t} )

cell_acc      = (预测标签正确的格子数) / (模型本步预测且在界内的格子总数)
edge_Jaccard  = |预测边 ∩ 系统观测边| / |预测边 ∪ 系统观测边|

AP_i = (1/T_i) · Σ_t AP_{i,t}
AP   = (1/N)   · Σ_i AP_i
```

`cell_acc` 逐格比对模型输出的 `CELL x,y,FREE/WALL` 与真值占用；
`edge_Jaccard` 比对模型输出的 `Place a is connected with Places b...` 与系统在线观测图。
两项只要有一项可算就取可用项的均值；两项都缺则该步 AP=0。

**7. 路径效率比 ER**

```
ER = (1/N) · Σ_i l_i / max(p_i, l_i)
```

与 SPL 同式但**不乘 S_i**，即失败局也计入，用来单独看「路走得直不直」。

**8. 探索覆盖率 COV**

```
COV = (1/N) · Σ_i ( |已观测到的可走格| / |地图全部可走格| )
```

**9. 卡死率 STK**

```
STK = Σ_i (该局触发卡死告警的步数) / Σ_i T_i
```

卡死告警由三个检测器定义（见第三节），**对基线和升级组用同一套检测器回溯计算**。

**10. 强制逃逸次数 GRD**

```
GRD = Σ_i (该局 guard 接管动作的次数)
```

基线没有该机制，恒为 0。

## 二、单步综合得分 DS（逐步明细）

每一步给出 5 个分项，全部落在 [0,1]，加权求和：

```
DS_t = 0.30·P_t + 0.20·V_t + 0.25·M_t + 0.15·C_t + 0.10·G_t
```

**P — 进度项（Progress）**，用真值 BFS 距离：

```
P_t = clip( (d_{t-1} − d_t + 1) / 2 , 0 , 1 )
```

即：靠近终点一步 → 1.0；距离不变（含原地转向）→ 0.5；走远一步 → 0.0。
**本步导致整局结束时**特殊处理：结束在终点 → 1.0，结束在非终点 → 0.0。
（`FORWARD` 踩上终点同样会结束整局，也记 1.0——判定依据是「是否结束在终点」，
而不是「动作是否为 STOP」。这一点在离线自检阶段被查出并修正过一次。）

**V — 新颖项（Novelty）**：

```
V_t = 1.00  首次踏入新格
    = 0.50  踏入以前走过的格
    = 0.25  原地转向（LEFT/RIGHT，未撞墙）
    = 0.00  撞墙（FORWARD 但前方是墙）
```

**M — 建图项（Map fidelity）**：

```
M_t = AP_{i,t}      （公式见第一节第 6 项）
```

**C — 干净项（Cleanliness）**：

```
C_t = 1.00  本步无卡死告警、无 guard 接管
    = 0.50  有卡死告警，但仍由模型自己决策
    = 0.00  本步被 guard 强制接管
```

**G — 承诺项（Goal commitment）**，考察模型有没有反复横跳：

```
G_t = 1.00  子目标与上一步相同
    = 1.00  上一步的子目标本步已到达
    = 0.75  上一步的子目标已失效（不再是 frontier，例如已走过或不可达）
    = 0.00  无理由改换子目标（反复横跳）
    = 0.50  未解析出 <SUBGOAL> 标签（中性值）
```

> 基线组的 prompt 没有 `<SUBGOAL>` 标签，因此基线每一步 G 恒取中性 0.5；
> 基线也没有 guard，因此 C 只可能是 1.0 或 0.5。这两点是**对基线有利**的设定，
> 对比时不会出现「靠新机制刷分」的情况。

**局级 DS**：`DS_i = (1/T_i) Σ_t DS_t`，`DS = (1/N) Σ_i DS_i`。

## 三、卡死检测器（三项，全部只用机器人自身轨迹，不偷看真值）

```
D1 OSCILLATION : 最近 4 个位置构成 A-B-A-B（A≠B）      -> 在两格间来回震荡
D2 REVISIT     : 当前格的累计访问次数 >= 3              -> 反复踩同一格
D3 STALL       : 最近 6 步内到终点的曼哈顿距离从未减小   -> 长时间没有实质进展
```

任一触发即记为「卡死步」（计入 STK）。

**两级响应**：

- **Tier A（提示层）**：把触发器名称、已重复访问的格子清单、确认死胡同清单写进 prompt，
  并强制要求「换一个锚点、走到一个从没站过的格子」。决策权仍在模型手里。
- **Tier B（强制逃逸 guard）**：**连续 3 步**处于卡死状态且没有踏上新格时，由程序接管一步——
  在四个自由邻格中选「访问次数最少、其次离终点曼哈顿最近」的一格，转向它 / 前进。
  每局最多接管 **5 次**（`guard_budget`），防止程序替模型跑完全程。
  每次接管都在日志里写 `[GUARD]` 行，并在逐步 CSV 里标 `source=GUARD, guard_override=1, C_t=0`。

## 四、升级项与评分的对应关系

| 升级 | 机制 | 主要影响的分项 |
|---|---|---|
| U1 锚点 | 在**已观测图**上按 `score(f)=d_known(robot→f)+manhattan(f→goal)` 排序，给出 Top-3 子目标；并把终点坐标翻译成自然语言方位 | P、G |
| U2 未探索路径入决策 | 列出全部 frontier、每方向未探索格数、确认死胡同、重复访问格；写入硬规则 R1–R5（此路不通立即切次优锚点） | V、P、COV |
| U3 防卡死 | 三检测器 + 提示层警告 + 强制逃逸 | C、STK、GRD |

> **诚实性声明**：锚点排序只用「系统已观测到的拓扑图」+ 指令中本来就公开的终点坐标，
> **不使用真值地图上的 BFS 距离**。真值 BFS 只出现在评测侧（P 项、NE），不进入 prompt。
> 需要指出的既有设定：本 2D demo 的指令里**直接给出了终点坐标**，这与原论文（R2R 只给自然语言）
> 不同，是上一版复现遗留的放宽条件，本次未改动以保持可比性；U1 额外把坐标转写成语言方位，
> 方向上更贴近论文「给关系、别给数字」的结论。
